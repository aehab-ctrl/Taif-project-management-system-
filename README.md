## الهوية البصرية الجديدة وثنائية اللغة

- **تصميم جديد**: شريط جانبي غامق بكامل الارتفاع، شريط علوي بتدرّج ذهبي، وأزرار/عناصر نشطة بلون بنفسجي مميز.
- **مبدّل لغة عربي/إنجليزي حقيقي** في الشريط العلوي: يبدّل اتجاه الصفحة بالكامل (RTL ⇄ LTR) ونصوص الواجهة (القوائم، الأزرار، العناوين، رؤوس الجداول). البيانات الفعلية المُدخلة (أسماء المشاريع، الأوصاف) تبقى بالعربية دائماً في كلا الوضعين، بحسب طلب واجهة فقط ثنائية اللغة.
- **مكتمل حالياً**: كامل نظام متابعة الخطط والمبادرات (اللوحة، المحاور والأهداف، المبادرات، المحفظة، الجدول الزمني، المخاطر، التقارير، النماذج، متابعة القيادات، مركز القرارات) مترجم بالكامل بأكثر من 340 عبارة واجهة.
- **قيد الإنجاز**: ترجمة واجهات الأنظمة الثلاثة الأخرى (المالي، المحاسبي، الموارد البشرية) — تعمل حالياً بالعربية بغض النظر عن اللغة المختارة، وسيتم استكمال ترجمتها لاحقاً بنفس الآلية.

## كيف تتكامل الأنظمة الأربعة معاً

```
الخطط والمبادرات  →  المالي والمشتريات  →  الرقابي والمحاسبي  →  الموارد البشرية
   (65 مشروعاً)      (طلبات/أوامر شراء)     (قيود مزدوجة تلقائية)    (رواتب فعلية)
        │                    │                       │                    │
        └──── الميزانية ─────┴──── الصرف الفعلي ──────┴──── تكلفة الموظفين ─┘
```

- كل **أمر صرف** "مصروف" في النظام المالي يُحدّث تلقائياً الصرف الفعلي للمشروع في نظام الخطط، **وينشئ قيداً محاسبياً مرحّلاً** في النظام الرقابي.
- كل **مسير رواتب** "مصروف" في نظام الموارد البشرية ينشئ تلقائياً قيداً محاسبياً (مدين رواتب / دائن بنك واستقطاعات مستحقة).
- **دليل الحسابات** واحد موحّد لكل الحركات المالية القادمة من المشتريات والرواتب.
- **الموظفون** يمكن ربطهم بمشروع محدد، فتظهر تكلفتهم في تقارير كل من الموارد البشرية ونظام الخطط.

## 1) نظام متابعة الخطط والمبادرات

تسلسل هرمي استراتيجي حقيقي مستخرج تلقائياً من محفظة الـ65 مشروعاً:
`الخطة الاستراتيجية → 6 محاور → 9 أهداف استراتيجية → 25 مبادرة → 65 مشروعاً`

- لوحة قيادة بإنجاز مرجّح بالميزانية، وجدول إنجاز حسب المحور.
- إدارة كاملة (CRUD) للمبادرات، مع مؤشرات أداء (KPI) قابلة للتعديل، وربط/إلغاء ربط المشاريع، وتقرير Word تلقائي.
- متابعة القيادات ومركز القرارات مبنية على الكيانات الحقيقية بدلاً من نص حر.

## 2) النظام المالي والمشتريات

- لوحة مالية: موازنة معتمدة، صرف فعلي، التزامات قائمة (Encumbrance)، متاح فعلياً.
- دورة مشتريات كاملة: طلب شراء (اعتماد) ← أمر شراء (استلام) ← أمر صرف.
- **تكامل مباشر**: أمر الصرف "مصروف" يُحدّث تلقائياً الصرف الفعلي للمشروع في نظام الخطط.
- سجل موردين وعقود كامل، مع تقرير Word لكل عقد وتصدير CSV لسجل المشتريات.

## 3) النظام الرقابي والمحاسبي

محاسبة كاملة بقيد مزدوج (Double-Entry)، مبنية تلقائياً فوق بيانات المشتريات والرواتب:

- دليل حسابات هرمي (19+ حساباً)، مع دفتر أستاذ تفصيلي لكل حساب.
- قيود يومية بتحقق آلي من التوازن (رفض أي قيد مدينه ≠ دائنه)، دورة مسودة ← ترحيل، وعكس القيد بدلاً من حذف المرحّل.
- **ميزان مراجعة، قائمة دخل، وقائمة مركز مالي** — تم اختبارها فعلياً: متزنة رياضياً بالكامل.
- مطابقة بنكية دورية، ورقابة داخلية مع توليد تلقائي لملاحظات من تجاوزات ميزانية المشاريع.
- تقارير Word لكل من الميزان، قائمة الدخل، والمركز المالي.

## 4) نظام الموارد البشرية (جديد)

- **الموظفون والهيكل التنظيمي**: 5 أقسام، سجل موظفين كامل (الراتب الأساسي والبدلات، نوع التعاقد، بيانات التواصل)، وربط اختياري بمشروع محدد.
- **الإجازات**: طلبات إجازة بدورة اعتماد (معلقة/معتمدة/مرفوضة)، تُحدّث حالة الموظف تلقائياً عند الاعتماد.
- **الحضور والانصراف**: سجلات حضور شهرية لكل موظف.
- **مسير الرواتب**: توليد مسير شهري تلقائي لكل الموظفين النشطين (بدلات + استقطاع تأمينات اجتماعية ٩.٧٥٪)، دورة مسودة ← اعتماد ← صرف.
- **تكامل محاسبي مباشر**: عند "صرف" المسير، يُنشأ تلقائياً قيد محاسبي (مدين رواتب وأجور / دائن بنك عن الصافي ودائن استقطاعات مستحقة) — تم اختباره فعلياً: القيد يوازن الميزان تماماً في كل مرة.
- **قسيمة راتب Word** لكل موظف، وتصدير CSV لسجل الرواتب الكامل.
- **ربط تكلفة الموارد البشرية بالمشاريع**: تقرير في لوحة الموارد البشرية يوضح التكلفة الشهرية لكل مشروع له موظفون مرتبطون به.

## الاختبار

تم اختبار النظام بالكامل فعلياً (وليس افتراضياً فقط) عبر محاكاة متصفح كاملة لكل مرحلة:
- توازن ميزان المراجعة وقائمة المركز المالي رياضياً في كل الحالات.
- تكامل المشتريات ↔ المحاسبة ↔ المشاريع (تحديث الصرف الفعلي تلقائياً وعكسه عند التراجع).
- تكامل الرواتب ↔ المحاسبة (فحص دقيق: دلتا البنك = -صافي الراتب، دلتا الرواتب = +الإجمالي، دلتا الاستحقاقات = +الاستقطاعات).
- الحماية من الصرف المزدوج، ومنع حذف القيود المرحّلة.
- ترحيل البيانات المحفوظة من أي إصدار سابق (خطط فقط ← + مالي ← + محاسبة ← + موارد بشرية) دون فقدان أي بيانات، مُتحقق من ذلك عبر محاكاة استخدام فعلي متسلسل للإصدارات.

## النشر على GitHub Pages

1. أنشئ مستودعاً جديداً على GitHub وارفع محتويات هذا المجلد كما هي (حافظ على مجلد `templates/`).
2. من إعدادات المستودع: **Settings → Pages**.
3. تحت **Source** اختر الفرع `main` والمجلد `/ (root)`، ثم اضغط **Save**.
4. بعد دقيقة أو دقيقتين سيصبح النظام متاحاً على: `https://<username>.github.io/<repo-name>/`

## ملاحظات هامة

- **البيانات محلية للمتصفح** عبر `localStorage` بالكامل — لا حاجة لخادم أو حساب أو اتصال إنترنت بعد التحميل الأول. لمشاركة البيانات بين أجهزة متعددة، استخدم "تصدير/استيراد نسخة احتياطية" من صفحة الإعدادات (تشمل بيانات الأنظمة الأربعة جميعها).
- لتغيير الشعار أو اسم النظام: صفحة **الإعدادات** داخل النظام.
- هوية بصرية متوافقة مع هوية جامعة الطائف (الذهبي `#D5B254` والأخضر `#537E54`).
- جميع البيانات المُدرجة مسبقاً (المشاريع، الموردون، الموظفون، القيود) بيانات أولية واقعية، وقابلة للتعديل أو الحذف بالكامل من الواجهة حسب بيانات جهتكم الفعلية.
